# 케어브릿지 (CareBridge)

> 외국인 요양보호사의 모국어 관찰메모를 **비식별 → 한국어 번역 → 장기요양 기록 항목 구조화 → 위험 신호 분류**까지 처리해,
> 돌봄인력 담당자가 검토·승인할 수 있는 한국어 기록 초안으로 만들어 주는 생성형 AI 서비스
> (2026 AI 라이프 솔루션 챌린지 출품작 · 아이디어 챌린지 수상 후보작 「케어브릿지」 구현)

## 핵심 기능
| 단계 | 내용 | 구현 |
|---|---|---|
| ① 입력 | 11개 언어 UI, 자유 서술 + 음성 입력 | `public/app.js` (Web Speech API) |
| ② 비식별화 | 이름·전화·주민번호·주소·호실·생년월일을 가명 토큰으로 **기기 안에서** 치환, 대상자 명부로 동일인 일관 가명 | `public/deid.js` |
| ③ 번역·구조화 | Gemini(`gemini-3.5-flash-lite`, 한도 초과·장애 시 대체 모델 자동 전환)로 충실 번역 + 요양기록 8개 항목 JSON 구조화, 원문에 없는 내용 생성 금지 | `lib/core.js` |
| ④ 위험 신호 | 즉시보고/당일확인/관찰 3단계, **원문 근거 인용** 필수 | `lib/core.js` 프롬프트 |
| ⑤ 안전장치 | 서버 2차 비식별, AI 잔여 PII 탐지, 응답 내 원본 PII 누출 검사, 사람 승인 전 ‘초안’ | `api/ai.js`, `deid.js` |
| ⑤-1 검토·QA 게이트 | 담당자가 승인·수정·보류 결정. 근거 보존(인용문이 원문에 있는지)·금지표현(진단·처방)·잔여 개인정보 자동 점검. **승인 전 복사·인쇄·가족 공유 차단**, 승인+QA 통과 기록만 가족 공유 미리보기(자동 전송 없음) | `public/qa.js`, `public/app.js` |
| ⑥ 역방향 소통 | 담당자 피드백 → 요양보호사 언어 번역 + 역번역 검증 | `lib/core.js` |
| ⑦ 기록 내보내기 | 승인 기록 CSV(엑셀) 저장, 서명란이 있는 인쇄용 기록지 | `public/app.js` |

## 로컬 실행
```bash
cp .env.example .env      # GEMINI_API_KEY 입력 (없으면 데모 모드)
node server.js            # http://localhost:3000
```
Node 18 이상, 외부 패키지 없음.

## 배포 (무료) — 테스트 URL 만들기
1. **Gemini API 키 발급**: https://aistudio.google.com/apikey → Create API key (무료 티어)
2. **GitHub**에 새 저장소 생성 후 이 폴더 업로드 (`.env`는 올리지 말 것)
3. **Vercel**(https://vercel.com) → GitHub로 로그인 → Add New Project → 저장소 Import
4. Settings → Environment Variables에 `GEMINI_API_KEY` 추가 → Deploy
5. 발급된 `https://<프로젝트>.vercel.app` 주소가 제출용 테스트 URL

키가 없어도 **데모 모드**(예시 메모 4종의 사전 생성 결과)로 화면 흐름은 시연 가능합니다.

## 사전검증(Pre-R&D)
```bash
node eval/eval_deid.js                        # 비식별화: 개발셋 36건(8개 언어)
node eval/eval_deid.js testset_holdout.json   # 비식별화: 홀드아웃 16건(9개 언어, 규칙 튜닝에 미사용)
node eval/eval_llm.js                          # 생성형 AI 구조화 품질 (API 키 필요)
npm test                                       # 비식별 엔진 회귀 테스트 (node --test)
```
| 평가셋 | 재현율 | 정밀도 | 일반표현 보존율 |
|---|---|---|---|
| 개발셋 v1(초기 규칙) | 87.8% | 100% | 97.4% |
| 개발셋 v2(개선 후) | 98.0% | 100% | 100% |
| 홀드아웃(미튜닝) | 72.0% | 100% | 100% |

**생성형 AI 구조화 (개발셋 36건, `gemini-3.5-flash-lite`)**

| 버전 | JSON 유효율 | 위험신호 재현율 | 수치 충실도 (엄격) | 근거 보존율 | 과잉경보 | 평균 응답 |
|---|---|---|---|---|---|---|
| v1 초기 프롬프트 | 100% | 86.1% | 70.8% | 미측정 | 0건 | 3.09초 |
| v2 프롬프트·지표 보완 | 100% | 94.4% | 90.5% (76.2%) | 미측정 | 1건 | 2.12초 |
| v3 최종 | 100% | 97.2% | 95.0% (80.0%) | 100% | 1건 | 2.18초 |

- 수치 충실도: v1 지표는 원문 "세 번"을 "3회"로 옮긴 올바른 변환까지 환각으로 셌다. v2부터 숫자 단어를 정규화했고, 기존 방식 값은 괄호(엄격)로 함께 남긴다.
- 근거 보존율: 위험 신호 인용문이 AI에 보낸 원문에 그대로 있는 비율. 서비스의 QA 게이트와 같은 함수(`public/qa.js`)로 잰다.
- v2·v3는 **개발셋을 보고 프롬프트를 조정한 결과**라 낙관적일 수 있다. 새 데이터로 다시 검증해야 한다.
- v3에 남은 실패: 복통 호소를 '심한 통증'(즉시보고)으로 올린 과잉경보 1건, "반 드셨어요"를 "50"으로 쓴 수치 창작 1건.

→ 규칙만으로는 처음 보는 표기(현지 전화번호 형식, 성 없는 이름, 몽골·네팔어 호칭 등)에 약함.
그래서 **대상자 명부(다국어 별칭) + AI 잔여 PII 탐지 + 서버 2차 비식별**의 다층 구조로 설계함.

※ 평가 데이터는 모두 개발자가 작성한 가상(합성) 메모이며, 실제 현장 데이터로 검증된 수치가 아님.

## 한계
- 프로토타입은 브라우저 저장소(localStorage)를 사용 → 실제 운영 시 기관 서버·권한관리 필요
- 의료적 판단을 대신하지 않음. AI 결과는 담당자 승인 전까지 ‘초안’
- 음성 입력은 브라우저(Chrome) 지원 언어에 한함
- 요양보호사 화면 11개 언어 문구는 개발자가 작성한 번역으로, 원어민 검수가 필요함
